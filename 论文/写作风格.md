# LAMF 论文写作风格指南

> 持续更新中 | 基于 VGDCFusion / HCLFuse 参考 + 实际写作迭代

---

## 一、全局立足点

**"Mamba基IVIF架构"** —— 以Mamba的选择性状态递推替代Transformer的密集全对等注意力。

核心叙事：

> Transformer自注意力的O(N²)全对等计算在IVIF中是过度建模——绝大多数像素对间无语义关联。Mamba的选择性状态递推（选择性记忆+选择性遗忘）天然更适合跨模态融合。用LESS-Mamba替换Transformer后，不仅复杂度从O(N²)降为O(N)，融合质量反而系统性提升——因为稀疏的、有选择性的上下文建模比密集的全对等注意力更契合IVIF任务的物理本质。

## 二、章节结构

| 章 | 写法 |
|------|------|
| 摘要 | 问题→缺陷分析（任务本质视角）→核心思路→两项改进→实验亮点→消融收束 |
| §1.1 简介 | 模态特性→互补性→应用场景（一句带过四个领域） |
| §1.2 范式演进 | "近年来...首先...其次...最后"自然流转，不用"第一代/第二代/第三代" |
| §1.3 贡献 | "首先...然后...最后"三段式，不编号，不嵌套(a)(b)(c)，每个贡献走三部曲 |
| §2 相关工作 | 方法概览（按类型分组）→ SSM原理背景 → 门控演进 |
| §3 方法 | 整体框架（公式+图文引用）→ LESS-Mamba → SimpleGate → 训练策略 |
| §4 实验 | 实验设置（实现细节+数据集+指标+消融变体表）→ 性能对比 → 消融 → 效率 → 下游 |
| §5 结论 | 总结 → 局限 → 未来 → 结语 |

## 三、句式与节奏

### 连接词偏好

| 场景 | 用词 | 示例 |
|------|------|------|
| 序列推进 | 首先...然后...最后 | "首先，我们提出了LESS-Mamba模块..." |
| 因果 | 从而 | "从而实现了信号与门控的结构性拆分" |
| 问题→方案 | 对此 | "对此本文通过在SS2D扫描前嵌入DWConv..." |
| 转折 | 然而 / 但 | "然而，该架构存在两个结构性问题" |
| 强调关键证据 | 值得注意的是 | "值得注意的是，MI的提升幅度与场景多样性呈正相关" |
| 递进 | 便是 / 其次便是 | "其次便是Detail分支的INN可逆耦合层..." |
| 结果收束 | 该结果表明了 | "该结果表明了Mamba的选择性状态递推..." |

### 句式规则

- **中等长度优先**：一句话不超过3个逗号。长句用分号拆平行结构。
- **对比用"前者...后者..."**："前者通过选择性记忆保留有效上下文、选择性遗忘跳过无关区域，后者则在所有像素对之间无差别地计算相似度。"
- **分号串联平行描述**："DWConv在SS2D展平扫描前预注入局部几何先验；SS2D四向选择性扫描以状态递推形式建模全局长程依赖；SimpleGate以零参数通道乘法实现局部增强与全局信息的自适应融合。"
- **先结论后细节**：每段开头一句给出该段的中心结论，后面再展开。

### 禁止句式

- ❌ "该设计具有以下三方面优势" → 直接写优势
- ❌ "优雅地解决了上述冲突" → 去掉自夸修饰词
- ❌ "从实证角度证明了" → "实验表明"即可
- ❌ 段落末尾的重复总结

## 四、贡献三部曲

每个贡献的固定结构：

```
提出了X，从而Y（效果预告）。
该模块/策略是Z（具体描述）。
[数据可选，放在实验部分更合适]
```

| 部曲 | 贡献1（LESS-Mamba） | 贡献2（SimpleGate） |
|------|------|------|
| 提出了什么 + 效果 | 提出了LESS-Mamba模块，从而能够更好的对跨模态信息进行融合，保留有效区域并且遗忘或者跳过无关区域 | 提出了SimpleGate双位点的部署策略，从而实现了信号与门控的结构性拆分，让门控信号能够从独立特征子空间自主学习而非被输入幅度刚性绑定 |
| 具体是什么 | 该模块是一个以DWConv→SS2D→SimpleGate三级联为核心的Base融合层 | 该策略将SimpleGate同步部署于LESS-Mamba内部（替代SiLU）和NAFDetailBlock中（替代INN可逆耦合层） |
| 具体作用 | DWConv...; SS2D...; SimpleGate...（分号串联） | 在Base全局信息选择和Detail高频纹理提纯两个物理维度上形成非冗余的双层门控体系 |

## 五、术语与措辞

### 常用术语

| 类别 | 术语 |
|------|------|
| 模块名 | LESS-Mamba, SimpleGate, NAFDetailBlock, SS2D, DWConv |
| 指标 | MI（互信息）, SF（空间频率）, SCD, VIF, Qabf, SSIM |
| 数据集 | TNO, RoadScene, M3FD, FMB |
| 基线 | CDDFuse |
| 变体 | A/C/D/D⁺/E |

### 措辞规则

- **"如"替代括号**："如人员、车辆等"而非"（人员、车辆等）"。"在TNO（极端热晕干扰）"——数据集名后用括号注释特征是允许的
- **口语化但不随意**："近些年流行的"、"便是"、"做到了"、"大量计算资源反而浪费在了"
- **冒号用于引出解释**："核心挑战：图像展平为一维序列破坏了邻域像素的空间连续性"
- **"做到了"vs"实现"**："无法做到跨模态特征的选择性提纯"——语气更果断
- **"结构性拆分"优于"结构性解耦"**——"拆分"更形象

## 六、删减原则

1. 砍掉自夸修饰："优雅地"、"从实证角度证明了"、"显著地"
2. 砍掉预告句："该设计具有以下三方面优势"、"具体而言有以下几点"
3. 砍掉段落末尾重复总结——正文已经说清楚的不需要在段末再复述
4. 贡献部分不放引用编号，保持散文流畅
5. 不嵌套列表：(a)(b)(c)全部展开为散文或分号串联
